## 1. 安全概述

MTSCOS AI 智能考试系统采用多层次安全架构，提供企业级安全防护能力，确保系统数据和用户隐私的安全。v17.22.0 版本进一步引入 VIKEY 硬件密钥 7 要素强认证全链路验证，强化超级管理员登录安全。

### 安全目标

| 目标 | 说明 |
|------|------|
| 数据机密性 | 保护敏感数据不被未授权访问 |
| 数据完整性 | 确保数据在存储和传输过程中不被篡改 |
| 系统可用性 | 保证系统服务持续可用 |
| 访问可控性 | 细粒度权限控制，最小权限原则 |
| 审计可追溯 | 完整的操作日志和审计记录 |

### 安全原则

- **纵深防御**：多层安全措施，层层防护
- **最小权限**：用户只拥有完成工作所需的最小权限
- **安全默认**：默认配置为安全状态
- **定期审计**：定期安全审计和漏洞扫描
- **持续改进**：基于反馈持续优化安全措施

## 3. 安全功能

### 3.1 企业级防火墙

系统内置企业级 AI 防火墙，支持以下安全规则：

| 规则 | 说明 | 检测方法 |
|------|------|---------|
| SQL 注入防护 | 检测并拦截 SQL 注入攻击 | 正则匹配 + 参数化查询验证 |
| XSS 防护 | 检测并拦截跨站脚本攻击 | HTML 转义 + 内容过滤 |
| 命令注入防护 | 检测并拦截命令注入 | 命令白名单 + 参数校验 |
| SSRF 防护 | 检测并拦截服务端请求伪造 | 目标地址白名单 |
| 文件包含防护 | 检测并拦截文件包含攻击 | 路径规范化 + 白名单 |
| 路径遍历防护 | 检测并拦截路径遍历攻击 | 路径规范化 + 边界检查 |
| 敏感文件防护 | 禁止访问敏感文件 | 文件路径黑名单 |
| 暴力破解防护 | 检测并阻止暴力破解尝试 | 登录失败次数限制 |
| 扫描器防护 | 检测并阻止自动化扫描 | 请求频率 + UA 特征识别 |
| API 限流 | 限制 API 请求频率 | 令牌桶算法 |

### 3.2 安全漏洞管理

系统内置安全漏洞管理系统，包含：

#### 漏洞特征库

| 漏洞类型 | 检测特征数量 | 修复方案数量 |
|----------|-------------|-------------|
| SQL 注入 | 5 | 3 |
| XSS | 4 | 3 |
| 命令注入 | 3 | 2 |
| SSRF | 2 | 2 |
| 路径遍历 | 2 | 2 |
| 文件包含 | 1 | 1 |

#### 攻击模拟引擎

- **SQL 注入模拟**：检测系统对 SQL 注入攻击的防护能力
- **XSS 模拟**：检测系统对 XSS 攻击的防护能力
- **防护效果评估**：自动评估安全防护效果

#### AI 闭环学习

安全知识自动同步到系统知识库，实现安全能力的持续进化。

### 3.3 代码安全扫描

系统内置代码安全扫描器，支持以下检测规则：

| 规则 | 说明 | 严重程度 |
|------|------|---------|
| eval 代码注入 | 检测使用 eval 执行动态代码 | 高危 |
| 命令注入 | 检测使用 subprocess 执行命令 | 高危 |
| 路径遍历 | 检测路径遍历漏洞 | 中危 |
| 硬编码密钥 | 检测硬编码的 API 密钥和密码 | 高危 |
| SQL 注入 | 检测 SQL 语句拼接 | 高危 |
| XSS 漏洞 | 检测未转义的用户输入 | 中危 |
| 文件上传漏洞 | 检测不安全的文件上传 | 高危 |
| 敏感信息泄露 | 检测日志中的敏感信息 | 中危 |
| 不安全的反序列化 | 检测不安全的反序列化操作 | 高危 |
| CSRF 漏洞 | 检测缺少 CSRF 防护的表单 | 中危 |
| 弱密码哈希 | 检测使用弱密码哈希算法 | 中危 |
| 不安全的随机数 | 检测使用不安全的随机数生成 | 中危 |
| 超时设置不当 | 检测缺少超时设置的网络请求 | 低危 |

### 3.4 AI 安全建议

系统 AI 引擎智能分析安全漏洞，生成优化建议和实施步骤：

1. **漏洞识别**：自动识别代码中的安全漏洞
2. **风险评估**：评估漏洞的严重程度和影响范围
3. **建议生成**：生成修复建议和实施步骤
4. **实施指导**：提供详细的修复指导

### 3.5 VIKEY 硬件密钥认证

v17.22.0 新增 VIKEY USB 硬件密钥全链路验证，超级管理员登录需 7 要素强认证：

| 要素 | 说明 |
|------|------|
| 用户名 | 标准用户名验证 |
| 密码 | 密码哈希校验 |
| 随机挑战码 | 6 位动态挑战码二次验证 |
| USB Key 序列号 | 硬件设备序列号绑定 |
| USB Key PIN | 硬件密钥 PIN 校验 |
| SSL 指纹 | 客户端 SSL 证书指纹验证 |
| 硬件绑定校验 | 机器硬件特征码绑定 |

## 4. 安全配置

### 环境变量配置

| 环境变量 | 说明 | 默认值 |
|----------|------|--------|
| SECURITY_FIREWALL_ENABLED | 启用安全防火墙 | 1 |
| VIKEY_FORCE_CHECK_ENABLED | VIKEY 强制检查 | 1 |
| VIKEY_SUPER_ADMIN_REQUIRED | 超管强制 VIKEY | 1 |
| API_RATE_LIMIT | API 限流（每秒请求数） | 100 |
| SESSION_TIMEOUT | 会话超时时间（秒） | 3600 |
| MAX_UPLOAD_SIZE | 最大上传大小（MB） | 50 |
| LOG_LEVEL | 日志级别 | INFO |

### SSL/TLS 配置

```bash
# 生成 SSL 证书
openssl req -x509 -newkey rsa:4096 -nodes -out cert.pem -keyout key.pem -days 365

# 启用 SSL 启动
python3 server_real_db.py --ssl --ssl-port 8443
```

### API 密钥管理

```bash
# 生成新的 API 密钥
python -c "import secrets; print(secrets.token_hex(32))"
```

### 安全配置文件

```python
# config/security.py
class SecurityConfig:
    SECRET_KEY = os.environ.get('SECRET_KEY', secrets.token_hex(32))
    SESSION_COOKIE_SECURE = True
    SESSION_COOKIE_HTTPONLY = True
    PERMANENT_SESSION_LIFETIME = timedelta(hours=1)
    MAX_CONTENT_LENGTH = 50 * 1024 * 1024
```

## 5. 安全最佳实践

### 开发安全

1. **参数化查询**：使用参数化查询防止 SQL 注入
2. **输入验证**：对所有用户输入进行验证和清理
3. **输出转义**：对所有输出进行 HTML 转义防止 XSS
4. **最小权限**：使用最小权限原则配置数据库用户
5. **敏感信息保护**：避免在日志中记录敏感信息

### 部署安全

1. **使用 HTTPS**：始终使用 HTTPS 加密传输
2. **定期更新**：定期更新依赖包和系统组件
3. **安全备份**：定期备份数据并验证备份完整性
4. **访问控制**：限制服务器访问权限
5. **日志监控**：实时监控系统日志

### 运维安全

1. **定期审计**：定期进行安全审计和漏洞扫描
2. **安全培训**：对开发人员进行安全培训
3. **应急预案**：制定安全事件应急预案
4. **权限审查**：定期审查用户权限

## 6. 安全事件响应

### 响应流程

```text
安全事件检测 → 事件分类 → 影响评估 → 应急响应 → 事件处理 → 恢复验证 → 事后分析
```

### 事件分类

| 级别 | 说明 | 响应时间 |
|------|------|---------|
| P0 | 紧急 - 系统被入侵或数据泄露 | 立即 |
| P1 | 高危 - 严重漏洞被利用 | 1 小时内 |
| P2 | 中危 - 安全漏洞存在但未被利用 | 24 小时内 |
| P3 | 低危 - 安全建议或改进项 | 7 天内 |

### 应急响应措施

1. **隔离受影响系统**：限制受影响系统的网络访问
2. **收集证据**：收集日志和相关证据
3. **修复漏洞**：立即修复安全漏洞
4. **恢复服务**：在安全环境下恢复服务
5. **通知相关方**：通知用户和相关部门

## 7. 漏洞报告流程

### 报告方式

1. **GitHub Issues**：在 GitHub 上创建安全相关的 Issue
2. **邮件报告**：发送邮件至 security@mtscos.com
3. **安全表单**：通过系统安全反馈表单提交

### 报告内容

请包含以下信息：

- 漏洞描述
- 复现步骤
- 影响范围
- 严重程度评估
- 建议修复方案

### 响应时间

| 严重程度 | 响应时间 | 修复时间 |
|----------|---------|---------|
| 紧急 | 24 小时内 | 7 天内 |
| 高危 | 48 小时内 | 14 天内 |
| 中危 | 1 周内 | 30 天内 |
| 低危 | 2 周内 | 60 天内 |

### 安全奖励

对于发现严重安全漏洞并提供有效修复方案的贡献者，我们会给予以下奖励：

- 在项目 README 中致谢
- 在安全文档中记录贡献
- 提供项目贡献者徽章
