| 维度 | 即梦 AI | 我们的引擎 | 差距 |
|------|---------|-----------|------|

## 五、即梦 AI 用到的 Prompt (从文件名反推)

文件名: `jimeng-2026-09-18-4393-从"自然的密码"标题卡平滑向前推进，画面自然过渡到数学公式卡片，同一次连续相机运.mp4`

> **即梦的 Prompt 写法**: 把每个镜头的**动态画面描述**都用口语化的方式写在自然语言里，而不是我们结构化的 JSON。即梦 seedance 理解自然语言比理解 JSON 结构更好。

## 六、仙女座引擎改进方向 (按优先级)

### 🔴 P0 必须修 (对比暴露的问题)

1. **无转场动画** —— ImageClip 直接拼接，需要加 moviepy `crossfadein/crossfadeout` 或自定义转场
2. **静态卡片帧重复** —— 每张卡片内应该加轻微动画 (文字渐入/卡片缩放呼吸)，而不是完全静止
3. **无背景音乐** —— 每条视频需要自动匹配一段 lo-fi/氛围 BGM (零版权)

### 🟡 P1 应该修

4. **视觉素材池** —— 光靠 Pillow 画卡片不够，应该让即梦 先生成关键帧图片 (text2image)，再用 moviepy 把图片拼成视频 (比纯卡片好太多)
5. **画面动态化** —— 每张卡片内的文字加 typewriter 打字动画/强调词放大特效
6. **竖屏分辨率** —— 即梦 704×1248 非标准，我们 1080×1920 其实更好，但 AI 应该能自适应输出

### 🟢 P2 可选

7. **多模型路由** —— 即梦 seedance 失败时，降级到 Kling/Runway/Hailuo 而不是 Pillow
8. **镜头语言学习** —— 把即梦的帧转成可复用的视觉模板库
9. **自动字幕合成** —— 用 edge-tts 输出的文本 + moviepy VideoClip 加字幕 overlay

## 七、即梦 Prompt vs 我们的 Prompt 对比

### 即梦 Web 版 Prompt (有效)
```
从"自然的密码"标题卡平滑向前推进，画面自然过渡到数学公式卡片，
同一次连续相机运动贯穿全程
```

**关键**: 把画面描述写成**导演的口语化分镜指令**，包含**运镜方式** (向前推进/平滑过渡/连续相机运动)

### 我们的 Jimeng CLI Prompt (无效, 被会员限制)
```
请为抖音生成一个关于「斐波那契」的竖屏短视频 (9:16, 1080p, 50-60秒)。
【完整旁白台词】...
【6个分镜画面】Shot 1 [title]: ... Shot 2 [formula]: ...
【风格要求】...
```

**问题**: 太像产品需求文档，AI 不喜欢这种格式。应该改成**导演口吻的自然语言**。
