## 失败项根因分析

### 根因：B1 全局权限守卫 catch-all 正则过宽匹配

**5 个失败全部源于同一根因**——审计表中的单段通配路由生成正则 `^/[^/]+$`，匹配**任何单段路径**。

**证据链** (审计表正则匹配测试):
```
/index                          → 匹配4条: /<path:copy_key>, /<test_id> (×2)  → login → 401
/home                           → 匹配4条: /<path:copy_key>, /<test_id> (×2)  → login → 401
/this_route_does_not_exist_...  → 匹配4条: /<path:copy_key>, /<test_id> (×2)  → login → 401 (应为404!)
/student/home                   → 匹配1条: /student/home (page_student/login) → 401 (应为302重定向)
```

**问题路由** (审计表中 11 条含 `<path:>` 通配，其中单段通配过于宽泛):
| 路由 | 类别 | suggested_role | 生成正则 | 问题 |
|------|------|----------------|----------|------|
| `/<path:copy_key>` | unknown | login | `^/[^/]+$` | 匹配所有单段路径 |
| `/<test_id>` (×2) | unknown | login | `^/[^/]+$` | 匹配所有单段路径 |

**影响**:
1. **公共别名误拦**: `/index`、`/home` 本应公开访问或重定向，被误判需登录→401
2. **404 页面失效**: 不存在的路径返回 401 而非 404，破坏异常页渲染
3. **页面路由重定向被覆盖**: `/student/home` 等页面路由自有 302 重定向登录逻辑，被守卫 abort(401) 提前拦截，用户体验降级（401 异常页 vs 302 跳转登录）

---

## 修复建议

### 建议1（P0 · 安全架构师 SEC_01）：排除单段通配路由 + 精确匹配
守卫 `_match_route_role` 应排除单段通配路由 `/<path:x>`、`/<param>`（过于宽泛），仅对**多段路径**或**精确字符串**路由做权限映射。catch-all 路由交由 Flask 自身 404/路由处理。

### 建议2（P1 · 前端架构师 FE_01）：页面路由用 302 而非 401
对 `page_*` 类别路由，未登录时应 302 重定向到登录页（用户体验友好），而非 abort(401)。仅 API 路由返回 401 JSON。

### 建议3（P1 · 张架构师 BE_01）：守卫优先级置于路由匹配之后
将守卫逻辑从 `before_request`（路由匹配前）调整为路由处理函数内或 `after_request`，让 Flask 先确定路由存在性（404 自然处理），再对已注册路由做权限校验。

### 建议4（P2 · AI赋能 AI_02）：登录态回归测试
修复后需补充登录态测试用例（admin/student session），验证登录后页面正常渲染、统计卡片填充真实数据、AI员工徽标显示。
