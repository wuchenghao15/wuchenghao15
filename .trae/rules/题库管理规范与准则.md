# MTSCOS AI 项目题库管理规范与准则

> **层级**: L2 操作 | **优先级**: 服从 [§14 IRON_RULE](§14强制开发12步骤独立约束规则.md) (L0) | **索引**: [规则总索引](00-规则总索引.md)

## 1. 总则

### 1.1 目的

为规范 MTSCOS AI 项目题库管理工作，确保题库内容的质量、准确性和完整性，建立统一的题库扩充与维护标准，特制定本规范。

### 1.2 适用范围

本规范适用于 MTSCOS AI 项目中所有题库管理活动，包括但不限于：

- 题目源管理
- 题目分类与标签管理
- 题目质量检查
- 题库扩充（AI 生成与手动添加）
- 题目生命周期管理
- 专项题库管理
- 题库统计与分析

### 1.3 核心原则

| 原则 | 说明 |
|------|------|
| **质量优先** | 所有题目必须经过严格的质量检查才能入库 |
| **分类清晰** | 题目必须按照统一的分类体系进行归类 |
| **标签规范** | 题目必须添加准确的标签便于检索和标准 |
| **来源可追溯** | 每道题目必须记录来源信息 |
| **定期维护** | 题库内容必须定期更新和清理 |
| **安全合规** | 题库内容必须符合法律法规和教育规范 |
| **巡检驱动** | 题库管理必须纳入 AI 巡检闭环，支持自动检测和修复 |
| **法律准则合规** | 所有题库管理活动必须遵循法律准则文件规定 |
| **自动修复闭环** | 发现题库问题自动触发修复流程，修复结果记录到数据库并投喂脑库 |

## 5. 题目质量检查规范

### 5.1 质量检查标准

题目必须通过以下质量检查：

| 检查项 | 标准 | 说明 |
|--------|------|------|
| **必填字段检查** | 所有必填字段必须存在且非空 | `id`, `subject`, `question`, `options`, `answer`, `difficulty` |
| **难度验证** | 难度值必须为有效值 | `简单`, `中等`, `困难` |
| **科目验证** | 科目必须为有效科目 | 见 3.2 节 |
| **题目长度检查** | 题目内容长度必须在 10-1000 字符之间 | 过短或过长都不符合要求 |
| **选项数量检查** | 选项数量必须在 2-6 个之间 | 保证题目的有效性 |
| **选项有效性检查** | 每个选项必须非空且为字符串 | 禁止空选项 |
| **答案有效性检查** | 答案必须在选项范围内 | 答案索引或内容必须有效 |
| **解析检查** | 解析内容至少 5 个字符 | 确保解析有意义 |
| **重复检查** | 题目内容和答案组合必须唯一 | 禁止重复题目 |

### 5.2 质量评分标准

| 评分项 | 权重 | 评分标准 |
|--------|------|---------|
| 题目完整性 | 30% | 所有字段完整得满分，缺失扣减 |
| 题目准确性 | 25% | 题目内容准确无误 |
| 选项合理性 | 20% | 选项具有混淆性，干扰项合理 |
| 解析质量 | 15% | 解析清晰、有指导性 |
| 标签准确性 | 10% | 标签准确反映题目内容 |

**质量等级划分**：

- **优秀**：80 分以上
- **良好**：60-79 分
- **待优化**：40-59 分
- **不合格**：40 分以下

### 5.3 质量检查流程

```text
提交题目 → 必填字段检查 → 格式验证 → 重复检测 → 质量评分 → 结果判定
                ↓
           检查通过？
              ↓
         是 → 入库
              ↓
         否 → 标记问题 → 返回修改
```

### 5.4 质量问题处理

| 问题类型 | 处理方式 |
|---------|---------|
| 格式错误 | 返回修改，自动标注错误位置 |
| 重复题目 | 拒绝入库，提示重复信息 |
| 质量评分过低 | 返回优化标准，人工审核 |
| 内容错误 | 标记问题，人工审核 |

## 6. 题库扩充流程规范

### 6.1 扩充方式

题库扩充支持以下方式：

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| **AI 自动生成** | 由 AI 员工自动生成题目 | 大规模扩充、专项题库生成 |
| **手动添加** | 人工录入题目 | 少量高质量题目、特殊题型 |
| **批量导入** | 通过文件批量导入题目 | 外部题库整合 |
| **题库同步** | 从教材教辅同步题目 | 与教材同步更新 |

### 6.2 AI 生成题目规范

AI 生成题目必须遵循以下规范：

| 规范项 | 要求 |
|--------|------|
| **题型多样性** | 必须包含多种题型，不能单一 |
| **难度分布** | 简单:中等:困难 ≈ 3:5:2 |
| **知识点覆盖** | 必须覆盖指定知识点范围 |
| **去重检查** | 生成后必须进行去重检测 |
| **质量评分** | 生成题目必须通过质量评分 |

### 6.3 AI 生成专项题目规范

#### 6.3.1 古诗文默写题

| 规范项 | 要求 |
|--------|------|
| 内容来源 | 必须来自经典古诗词库 |
| 出题方式 | 随机挖空，保留上下文 |
| 答案完整性 | 必须包含作者和作品名 |
| 解析要求 | 必须包含作品背景和诗句含义 |

#### 6.3.2 作文题目

| 规范项 | 要求 |
|--------|------|
| 题目类型 | 命题作文、话题作文、材料作文 |
| 字数要求 | 根据学段设置（600/800/1000 字） |
| 写作要求 | 明确文体、立意、选材要求 |
| 评分标准 | 提供评分参考维度 |

#### 6.3.3 公式运用题

| 规范项 | 要求 |
|--------|------|
| 公式准确性 | 必须使用正确的公式 |
| 应用场景 | 必须结合实际应用场景 |
| 解题步骤 | 必须提供完整解题步骤 |

### 6.4 审核流程规范

所有新题目必须经过审核才能发布：

```text
提交 → AI 初检 → 人工审核 → 发布
         ↓
     自动通过/修改/拒绝
```

| 审核级别 | 触发条件 | 审核要求 |
|---------|---------|---------|
| **AI 自动审核** | 质量评分 ≥ 80 分 | 自动通过入库 |
| **人工审核** | 质量评分 60-79 分 | 人工确认后入库 |
| **重点审核** | 质量评分 < 60 分 | 修改后重新提交 |

## 7. 题目生命周期管理规范

### 7.1 题目状态

| 状态 | 说明 | 操作 |
|------|------|------|
| `draft` | 草稿 | 可编辑、可删除 |
| `pending_review` | 待审核 | 等待审核，不可修改 |
| `approved` | 已审核 | 可发布 |
| `published` | 已发布 | 可使用，可下架 |
| `archived` | 已归档 | 不可使用，可恢复 |
| `deleted` | 已删除 | 不可恢复 |

### 7.2 状态流转

```text
draft → pending_review → approved → published → archived/deleted
         ↓                     ↓
    rejected ←←←←←←←←←←←←←←←
```

### 7.3 题目过期管理

| 规则 | 说明 |
|------|------|
| 过期触发 | 题目超过 180 天未更新自动触发审核 |
| 审核流程 | AI 分析 + 人工确认 |
| 处理结果 | 更新内容或标记为过期 |

### 7.4 题目清理规范

| 清理类型 | 条件 | 处理方式 |
|---------|------|---------|
| **质量清理** | 质量评分 < 40 分 | 自动标记待优化 |
| **过期清理** | 超过有效期且未更新 | 自动归档 |
| **重复清理** | 检测到重复 | 保留高质量版本 |

```python
def handle_qb_anomaly(anomaly_type, question_ids, operator=None):
    """题库异常统一处理(EigenFlux + SSOT + 双表审计)"""
    # 1. 映射5级规则层级
    rule_level = _qb_anomaly_to_rule_level(anomaly_type)
    # 2. 记录违例审计
    _record_rule_violation_audit(
        event_code=anomaly_type,
        rule_level=rule_level,
        resource_type='question',
        resource_ids=question_ids,
        operator=operator
    )
    # 3. L0-L2自动触发EigenFlux AI5人磋商
    if rule_level in ('IRON_RULE','RED_LINE','RED_WALL'):
        try:
            ef = requests.post('/api/eigenflux/report_anomaly', timeout=5, json={
                'event_code': anomaly_type,
                'rule_level': rule_level,
                'details': {'question_ids': question_ids[:20]},
                'ai_panel': ['upgrade_analyst','compliance_auditor',
                            'security_auditor','dba','implementation_engineer']
            }).json()
            # 4. ≥4/5通过才执行自动修复
            if ef.get('vote_pass_rate', 0) >= 0.8:
                _apply_qb_recommended_fix(ef['recommendation'], question_ids)
                _log_qb_fix_applied(anomaly_type, ef['recommendation'])
        except Exception:  # fetch失败静默降级
            pass  # 不阻塞业务，仅记录日志
    # 5. 投喂脑库：异常+修复案例持续学习
    _feed_brain_knowledge('qb_anomaly_fix', {
        'type': anomaly_type, 'level': rule_level,
        'count': len(question_ids)
    })
    # 6. 冷却60秒/类，防重复触发
    _set_anomaly_cooldown(anomaly_type, cooldown_sec=60)
```
