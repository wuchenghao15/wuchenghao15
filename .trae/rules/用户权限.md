## 5. 权限检查流程

```text
1. 用户登录时验证身份
2. 根据用户角色加载权限列表
3. 权限列表缓存到session
4. 访问资源时检查权限缓存
5. 权限变更时刷新缓存
6. 记录权限操作审计日志
7. 超级管理员额外检查VIKEY认证
```

### 5.1 权限检查函数

```python
def has_permission(role, permission):
    """检查角色是否有指定权限"""
    perms = get_role_permissions(role)
    if '*' in perms:
        return True
    return permission in perms

def can_access(role, required_role):
    """检查角色是否可以访问需要特定角色的资源"""
    if role == 'super_admin':
        return True
    return get_role_level(role) >= get_role_level(required_role)
```

```python
def audit_log(user_id, action, module, resource, status, details):
    """记录审计日志"""
    with self.lock:
        conn = self._get_connection()
        cursor = conn.cursor()
        cursor.execute('''
            INSERT INTO audit_logs 
            (user_id, action, module, resource, status, details, created_at)
            VALUES (?, ?, ?, ?, ?, ?, ?)
        ''', (user_id, action, module, resource, status, details, datetime.now().isoformat()))
        conn.commit()
        conn.close()
```

## 11. 规则审批流程权限规范

### 11.1 7步审批流程角色权限矩阵

规则修改必须遵循以下7步审批流程，各步骤角色权限严格分离：

| 审批步骤 | 角色要求 | 权限代码 | 说明 |
|---------|---------|---------|------|
| Step 1: 管理员提议 | admin+ | `propose_rule_change` | 任何管理员及以上可发起规则修改提议 |
| Step 2: ≥2管理员同意 | admin+ (非提议人) | `approve_rule_proposal` | 需≥2名非提议管理员投票同意 |
| Step 3: EigenFlux AI5人磋商 | AI员工组 | `eigenflux_deliberate` | 升级分析师、合规审计员、安全审计员、DBA、实施工程师 5人投票，≥4/5通过 |
| Step 4: AI防火墙复审 | system_admin+ | `ai_firewall_review` | AI防火墙自动复审规则冲突和安全风险 |
| Step 5: 超级管理员终审 | super_admin (wuchenghao15) | `final_approve_rule` | 必须通过VIKEY实时检测，选择「立即适配」或「2个工作日后」 |
| Step 6: 适配期生效 | 系统自动 | - | 根据终审选择的适配时间自动生效 |
| Step 7: 保密撤回 (仅SA) | super_admin (wuchenghao15) | `withdraw_rule_proposal` | 内存标记，数据库/日志完全保密，无痕操作 |

### 11.4 EigenFlux AI5人磋商角色定义

规则审批Step 3必须由以下5名AI员工共同磋商，投票≥4/5方可通过：

### 11.6 _super_admin_vikey_check() 7要素认证权限

| 要素编号 | 校验项 | 权限要求 | 失败错误码 | 阻断范围 |
|---------|-------|---------|-----------|---------|
| 1. 用户名匹配 | 精确匹配 `wuchenghao15` | public | PERM_SA_USERNAME_MISMATCH | 登录/所有敏感操作 |
| 2. 密码哈希校验 | bcrypt+salt + SA保留名拦截 | public | PERM_SA_PASSWORD_INVALID | 登录/敏感操作 |
| 3. 随机挑战码 | 6位动态码一次性有效 | public | PERM_SA_CHALLENGE_FAIL | 敏感操作 |
| 4. VIKEY USB序列号 | 硬件加密狗序列号白名单 | public (检测) | VIKEY_REQUIRED | 所有SA操作，阻断 |
| 5. VIKEY PIN码 | 加密狗6位PIN，3次失败锁1h | public (验证) | VIKEY_PIN_LOCKED | 所有SA操作，阻断 |
| 6. SSL证书指纹 | 当前连接指纹白名单绑定 | public (后端) | SSL_FINGERPRINT_MISMATCH | 建议阻断+警告 |
| 7. 硬件指纹绑定 | CPU+主板+网卡MAC三绑定 | public (后端) | HARDWARE_BIND_FAIL | 强阻断，SA可特批绕过 |

```python
def _super_admin_vikey_check(operation_type='sensitive'):
    """SA VIKEY实时检测，桌面端USB+移动端指纹双路径
    - 桌面端: 每3秒轮询/api/vikey/hotplug_notify检测硬件插入
    - 移动端: 校验X-Fingerprint header
    - 失败: 返回VIKEY_REQUIRED 403错误 + 阻断操作
    - 通过: AI防火墙复审 + 终审标记 → 可执行SA专属操作
    """
    vikey_status = _detect_vikey_usb()  # 序列号白名单
    x_fp = request.headers.get('X-Fingerprint')
    if not vikey_status['inserted'] and not x_fp:
        return jsonify({
            'code': 403, 'error': 'VIKEY_REQUIRED',
            'message': 'SA敏感操作需插入VIKEY USB加密狗或移动端指纹认证',
            'operation_type': operation_type
        }), 403
    if x_fp and not _verify_mobile_fingerprint(x_fp):
        return {'code': 403, 'error': 'FINGERPRINT_INVALID'}, 403
    _ai_firewall_review_sa_operation(operation_type)  # AI复审
    return None
```
