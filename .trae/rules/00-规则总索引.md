## 3. 交叉引用关系

### 3.1 §14 IRON_RULE（L0最高优先级）
- **所有其他规则必须服从§14 IRON_RULE**
- 任何开发活动（新建功能、修改代码、修复Bug、调整配置）必须先走12步骤
- 参见: [§14强制开发12步骤独立约束规则.md](§14强制开发12步骤独立约束规则.md)

### 3.5 规则治理与一致性
- `规则治理与一致性规范.md` 负责规则文件自身的生命周期和一致性，不改变 L0 状态机。
- `STATUS: ACTIVE` 才能参与执行；备份、归档和快照只用于追溯。
- 规则冲突必须按层级、适用范围、更新时间和可验证性裁决；不能裁决时标记 `NEEDS_REVIEW` 并停止扩大变更。
- 新增、重命名、废弃规则必须同步更新本索引的清单、数量、版本快照和变更日志。

### 3.2 开发规则 → 其他规则
- 开发活动 → 遵循 `开发规则.md` 目录结构和代码规范
- UI开发 → 遵循 `设计规范.md` Element Plus设计Token
- 路由/API → 遵循 `用户权限.md` @system_container装饰器 + 防盗链拦截
- AI组件 → 遵循 `AI系统操作规范.md` AI员工/引擎/脑库操作
- 系统功能 → 遵循 `系统操作规范.md` 子系统操作
- 参数管理 → 遵循 `系统参数数据规范与操作规范.md` 参数分类/验证
- 源码修改 → 遵循 `源码修改准则参考与思路方案.md` 修改流程
- 题库管理 → 遵循 `题库管理规范与准则.md` 题目质量/分类
- Arduino页面 → 遵循 `用户权限.md` 仅wuchenghao15可访问

### 3.3 权限规则交叉
- 超级管理员(wuchenghao15): 7要素强认证 + VIKEY加密狗 → 见 `用户权限.md` §1.1
- @system_container装饰器: 4级(guest/login/admin/super_admin) → 见 `用户权限.md` §2

- 防盗链拦截: 非首页Referer + 未授权session → 重定向到/index

### 3.4 自动化引擎规则交叉
- 自动化进程 → 遵循 `AI系统操作规范.md` AI引擎/集群操作规范

## 8. 规则版本变更日志

> **所有规则修改必须写入 `mt_rule_changelog` 表, 通过7步审批流程 (用户权限.md §3.3)**

| 字段 | 说明 |
|------|------|
| `rule_id` | 规则代码 (如 MT_IRON_RULE_12STEPS) |
| `from_version` / `to_version` | 版本变更 (如 v1.0.0 → v1.1.0) |
| `change_type` | MAJOR / MINOR / PATCH / META |
| `approved_by_7step` | 7步审批是否通过 (0/1) |
| `sa_final_decision` | SA终审决定 (立即适配 / 2个工作日后 / 驳回) |
| `sa_vikey_verified` | SA VIKEY 是否实时检测 (0/1) |
| `eigenflux_panel_json` | EigenFlux 5人磋商记录 |
| `admin_approvers_json` | 2名非提议管理员同意记录 |
| `is_secret_withdrawn` | 是否保密撤回 (0/1, 仅SA可用) |

**版本号 bump 规则**:
- `MAJOR` (vX.0.0): 新增/删除整章规则
- `MINOR` (v0.X.0): 新增条款或修改强制条款
- `PATCH` (v0.0.X): 文档表述优化/错别字
- `META`:         仅更新 RULE_META, 版本号不动

**查询最新变更**:
```sql
SELECT rule_id, to_version, change_type, change_summary, sa_final_decision, created_at
FROM mt_rule_changelog
ORDER BY created_at DESC
LIMIT 10;
```
