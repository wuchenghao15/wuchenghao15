# MTSCOS AI 项目开发规则

## 1. 开发原则

> **核心原则**：规范、安全、可维护、可扩展、巡检驱动

所有开发活动（新建功能、修改代码、维护增强）必须遵循本规则和《设计规范》。任何偏离规则的代码将被拒绝合并，并自动触发巡检引擎检测。

### 1.1 巡检驱动开发

| 原则 | 说明 |
|------|------|
| **巡检优先** | 所有代码变更必须通过 AI 巡检引擎检查 |
| **自动修复** | 检测到的问题自动触发修复流程 |
| **法律准则合规** | 所有开发活动必须遵循法律准则文件规定 |
| **错误上报** | 运行时错误自动上报到数据库 |
| **学习闭环** | 修复经验自动积累到脑库 |

## 3. 代码规范

### 3.1 Python代码规范

#### 3.1.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块名 | 小写，下划线分隔 | `auth_service.py` |
| 类名 | 大驼峰 | `AuthService` |
| 方法名 | 小写，下划线分隔 | `get_user_by_id()` |
| 变量名 | 小写，下划线分隔 | `user_id` |
| 常量名 | 全大写，下划线分隔 | `MAX_RETRY_COUNT` |
| 蓝图名 | 小写，下划线分隔 | `admin_api` |

#### 3.1.2 代码风格

- 使用 **4空格缩进**（禁止使用Tab）
- 行宽不超过 **120字符**
- 每行一个语句，禁止多语句同行
- 使用类型提示（Type Hints）
- 模块级函数和类必须有文档字符串（Docstring）

#### 3.1.3 路由规范

```python
# 蓝图注册（app/routes/__init__.py）
from flask import Blueprint

admin_api = Blueprint('admin_api', __name__)

# 路由定义（app/routes/admin_api.py）
from . import admin_api
from app.services.admin_service import AdminService

@admin_api.route('/api/admin/users', methods=['GET'])
def get_users():
    """获取用户列表"""
    service = AdminService()
    users = service.get_users()
    return {'code': 200, 'data': users}
```

#### 3.1.4 模型规范

```python
# app/models/user.py
from app.extensions import db

class User(db.Model):
    """用户模型"""
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(64), unique=True, nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)
    
    def to_dict(self):
        """转换为字典"""
        return {
            'id': self.id,
            'username': self.username,
            'email': self.email
        }
```

#### 3.1.5 服务层规范

- 路由层**不包含**业务逻辑，仅负责参数接收和响应格式化
- 业务逻辑必须放在**Service层**
- Service层可以调用其他Service，但禁止循环依赖

#### 3.3.3 API调用规范

```javascript
// 使用统一的API调用函数
async function apiRequest(url, options = {}) {
    const defaultOptions = {
        headers: {
            'Content-Type': 'application/json',
            'X-Requested-With': 'XMLHttpRequest'
        },
        credentials: 'same-origin'
    };
    
    const response = await fetch(url, { ...defaultOptions, ...options });
    const data = await response.json();
    
    if (data.code !== 200) {
        throw new Error(data.message || '请求失败');
    }
    
    return data.data;
}
```

## 4. 异常处理规范

### 4.1 异常体系

所有非系统级异常必须使用自定义异常类：

```python
from app.exceptions import (
    AppException,
    AuthenticationException,
    AuthorizationException,
    ValidationException,
    ResourceNotFoundException,
    BusinessException
)
```

### 4.2 异常使用场景

| 异常类 | 使用场景 | HTTP状态码 |
|--------|---------|-----------|
| `AuthenticationException` | 未登录、Token过期 | 401 |
| `AuthorizationException` | 权限不足 | 403 |
| `ValidationException` | 参数校验失败 | 400 |
| `ResourceNotFoundException` | 资源不存在 | 404 |
| `BusinessException` | 业务逻辑错误 | 400 |
| `AppException` | 通用业务异常 | 400 |

### 4.3 异常抛出示例

```python
from app.exceptions import ValidationException

def create_user(data):
    if not data.get('username'):
        raise ValidationException(
            message='用户名不能为空',
            error_type='VALIDATION_ERROR',
            suggestion='请输入用户名',
            details={'field': 'username'}
        )
```

### 4.4 异常处理

所有异常由 `ExceptionHandler` 统一捕获，返回标准格式响应：

```json
{
    "code": 400,
    "message": "错误消息",
    "error_id": "abc12345",
    "timestamp": "2026-07-11T10:00:00",
    "category": "BUSINESS",
    "error_type": "VALIDATION_ERROR",
    "suggestion": "解决建议",
    "details": {}
}
```

## 5. API规范

### 5.1 响应格式

所有API响应必须遵循以下格式：

```json
{
    "code": 200,
    "message": "success",
    "data": {},
    "timestamp": "2026-07-11T10:00:00"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码，200表示成功 |
| `message` | string | 消息描述 |
| `data` | any | 响应数据 |
| `timestamp` | string | ISO8601时间戳 |

### 5.2 错误响应格式

```json
{
    "code": 400,
    "message": "错误消息",
    "error_id": "abc12345",
    "timestamp": "2026-07-11T10:00:00",
    "category": "BUSINESS",
    "error_type": "VALIDATION_ERROR",
    "suggestion": "解决建议",
    "details": {}
}
```

### 5.3 HTTP状态码

| 状态码 | 含义 | 使用场景 |
|--------|------|---------|
| 200 | OK | 请求成功 |
| 201 | Created | 资源创建成功 |
| 400 | Bad Request | 参数错误、业务逻辑错误 |
| 401 | Unauthorized | 未认证、Token过期 |
| 403 | Forbidden | 权限不足 |
| 404 | Not Found | 资源不存在 |
| 429 | Too Many Requests | 请求过于频繁 |
| 500 | Internal Server Error | 系统错误 |

## 6. 安全规范

### 6.1 环境变量

- 敏感信息（数据库密码、API密钥、JWT密钥）必须通过环境变量配置
- `.env` 文件必须添加到 `.gitignore`
- 提供 `.env.example` 文件作为配置模板

### 6.2 输入验证

- 所有用户输入必须进行验证（使用 `wtforms` 或自定义验证）
- 禁止直接使用用户输入拼接SQL语句（使用参数化查询）
- 禁止直接使用用户输入渲染HTML（使用Jinja2自动转义）

### 6.3 认证授权

- 使用JWT进行身份认证
- 使用权限装饰器验证用户权限
- 权限等级从高到低：HARDWARE_ADMIN > SUPER_ADMIN > ADMIN > NORMAL_USER

### 6.4 文件上传

- 限制上传文件类型和大小
- 文件存储路径不暴露给前端
- 使用安全的文件名（避免路径遍历攻击）

```python
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s'

logger = logging.getLogger(__name__)
```

## 13. Agent规范

### 13.1 Agent类型

| 类型 | 用途 | 示例 |
|------|------|------|
| `system` | 系统级Agent，管理系统配置和监控 | 系统管理员助手、监控Agent |
| `user` | 用户级Agent，辅助用户操作 | 学生学习助手、家长端助手 |
| `assistant` | 辅助型Agent，提供专业辅助 | 教师助手、学习分析助手 |
| `worker` | 工作型Agent，执行具体任务 | 代码开发助手、数据分析师 |
| `monitor` | 监控型Agent，实时监控系统状态 | 系统监控Agent、主动AI 助手 |

### 13.2 Agent命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| Agent代码 | `AGENT_<功能>_<编号>` | `AGENT_SYS_ADMIN_001` |
| Agent名称 | 中文描述性名称 | 系统管理员助手 |
| 文件命名 | 小写，下划线分隔 | `agent_manager.py` |

### 13.3 Agent生命周期

| 状态 | 说明 |
|------|------|
| `stopped` | 已停止，未运行 |
| `initializing` | 初始化中，准备启动 |
| `running` | 运行中，正常工作 |
| `paused` | 已暂停，可恢复 |
| `error` | 出错，需排查 |

## 17. 数据库Schema兼容性规范

### 17.1 Schema变更原则

| 原则 | 说明 |
|------|------|
| 向后兼容 | 新增字段必须有默认值，不允许删除已有字段 |
| 字段映射 | 旧字段名与新字段名必须提供映射机制 |
| 迁移脚本 | 所有Schema变更必须有对应的迁移脚本 |
| 版本记录 | 记录每次Schema变更的版本号和变更内容 |

### 17.2 表结构兼容性处理

所有模型创建表时必须检测并兼容已有表结构：

```python
@classmethod
def _create_table(cls):
    """创建表（必须兼容已有结构）"""
    try:
        db_manager.execute(f"""
            CREATE TABLE IF NOT EXISTS {cls.TABLE_NAME} (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                name TEXT NOT NULL,
                description TEXT
            )
        """)
        cls._add_missing_columns()
    except Exception as e:
        logger.error(f"创建表失败: {str(e)}")

@classmethod
def _add_missing_columns(cls):
    """添加缺失的列（保持向后兼容）"""
    columns_to_add = [
        ('status', "TEXT DEFAULT 'draft'"),
        ('created_at', "TIMESTAMP DEFAULT CURRENT_TIMESTAMP"),
        ('updated_at', "TIMESTAMP DEFAULT CURRENT_TIMESTAMP")
    ]
    for col_name, col_def in columns_to_add:
        try:
            db_manager.execute(f"ALTER TABLE {cls.TABLE_NAME} ADD COLUMN {col_name} {col_def}")
        except Exception:
            pass
```

### 17.3 字段名变更规范

| 变更类型 | 处理方式 |
|---------|---------|
| 字段重命名 | 保留旧字段，新增新字段，提供映射 |
| 字段类型变更 | 使用ALTER COLUMN或创建新字段 |
| 字段删除 | 标记为deprecated，不物理删除 |

### 17.4 Schema迁移脚本

所有Schema变更必须有迁移脚本，放在 `scripts/migrations/` 目录：


## 22. 前端错误捕获规范

### 22.1 全局错误捕获

所有前端页面必须在base.html中实现全局错误捕获：

```javascript
// base.html - 全局错误捕获
window.onerror = function(message, source, lineno, colno, error) {
    reportError({
        type: 'javascript_error',
        message: message,
        source: source,
        line: lineno,
        column: colno,
        stack: error ? error.stack : '',
        url: window.location.href,
        userAgent: navigator.userAgent
    });
    return true;
};

window.addEventListener('unhandledrejection', function(event) {
    reportError({
        type: 'promise_rejection',
        message: event.reason ? String(event.reason) : 'Promise rejected',
        source: 'unhandledrejection',
        line: 0,
        column: 0,
        stack: event.reason ? (event.reason.stack || '') : '',
        url: window.location.href,
        userAgent: navigator.userAgent
    });
});

// 覆盖console.error
const originalError = console.error;
console.error = function(...args) {
    originalError.apply(console, args);
    reportError({
        type: 'console_error',
        message: args.map(arg => typeof arg === 'object' ? JSON.stringify(arg) : String(arg)).join(' '),
        source: 'console.error',
        line: 0,
        column: 0,
        url: window.location.href,
        userAgent: navigator.userAgent
    });
};

function reportError(errorData) {
    fetch('/api/ai_inspection/console_error', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'X-CSRF-Token': document.querySelector('meta[name="csrf-token"]')?.content || ''
        },
        body: JSON.stringify(errorData)
    }).catch(() => {});
}
```

### 22.2 错误上报规则

| 错误类型 | 上报方式 | 存储位置 |
|---------|---------|---------|
| JavaScript语法错误 | window.onerror | ai_inspection_console_errors |
| Promise未捕获异常 | unhandledrejection | ai_inspection_console_errors |
| console.error调用 | 重写console.error | ai_inspection_console_errors |
| 网络请求错误 | fetch拦截 | ai_inspection_console_errors |
| 资源加载错误 | error事件监听 | ai_inspection_console_errors |

### 22.3 错误处理流程

```text
1. 前端捕获错误（window.onerror/unhandledrejection/console.error）
2. 构建错误数据（类型、消息、堆栈、位置等）
3. 发送到后端API /api/ai_inspection/console_error
4. 后端存储到ai_inspection_console_errors表
5. 巡检引擎定期扫描并尝试自动修复
```

### 24.3 VIKEY状态检测

```javascript
// VIKEY状态检测（每2秒轮询）
function startVikeyDetection() {
    setInterval(async () => {
        try {
            const response = await fetch('/api/vikey/detect');
            const data = await response.json();
            if (data.status === 'removed') {
                handleVikeyRemoved(data);
            }
        } catch (error) {
            console.error('VIKEY检测失败:', error);
        }
    }, 2000);
}

function handleVikeyRemoved(data) {
    // 显示红色横幅提示
    showBanner('VIKEY已拔出，系统将在3秒后锁定', 'danger');
    
    // 保存系统快照
    fetch('/api/vikey/snapshot/save', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' }
    }).then(response => response.json())
      .then(result => {
          if (result.success) {
              showBanner(`快照已保存: ${result.snapshot_id}`, 'warning');
          }
      });
    
    // 3秒后跳转登录页
    setTimeout(() => {
        window.location.href = '/auth/login';
    }, 3000);
}
```
